What goes in, what comes out
you send
{
  "document": "my bill was charged twice, please help",
  "questions": {
    "category": ["billing", "technical", "sales", "spam"],
    "urgent":   ["yes", "no"]
  }
}
You declare the options. That list is the contract. The answer will be one of these.
↓
the model sees
mybillwaschargedtwicepleasehelp billingtechnicalsalesspam
One flat sequence, here for the category question. The options are appended as ordinary words, so the model reads the document and the candidate answers together. The second question reuses the document's work rather than re-reading it.
↓
you get back
category
billing
p = 0.59
runner-up
technical
p = 0.27
urgent
yes
p = 0.88
confidence
0.41
low, route to a human
Typed values, not text. Every probability set sums to 1 over the options you listed, so there is nothing to parse and nothing to validate.
